## 2. ⚠️ УПРОСТИТЬ: Builder Pattern

### Где находится:
- **Строки 257-282**: "Решение 2: Builder Pattern для конфигурации"
- **Строки 779-856**: "Фаза 3: Builder и конфигурация"
- **Строки 1042-1063**: Пример с Builder в документации
- **Строки 1109-1116**: Пример выбора устройств через Builder

### Почему упростить:
- Builder это overkill для простого конфига
- Достаточно одного способа конфигурации: `VoiceAssistant.create(config)`
- Builder добавляет дополнительный слой абстракции
- Для 90% случаев достаточно простого объекта конфигурации

### Что оставить:
```typescript
// Простой конфиг - достаточно для всех случаев
const assistant = await VoiceAssistant.create({
    ai: { model: 'deepseek/...' },
    stt: { model: 'base' },
    tts: { voice: 'ru-RU' },
    devices: { input: 'mic-1', output: 'speaker-2' }
});
```

### Что убрать:
- Класс `VoiceAssistantBuilder`
- Методы `withMode()`, `withAI()`, `withSTT()`, `withTTS()`, `withDevices()`, `withKeyword()`
- Метод `build()`
- Валидацию в Builder (перенести в `VoiceAssistant.create()`)

## 3. ⚠️ УПРОСТИТЬ: Orchestrator

### Где находится:
- **Строки 233-247**: Диаграмма с Orchestrator
- **Строки 400-469**: "1.2 Создать Orchestrator для управления потоком"

### Почему упростить:
- Orchestrator это просто прослойка между VoiceAssistant и модулями
- Можно встроить эту логику прямо в VoiceAssistant
- Меньше классов = проще понять
- Не нарушает принципы, если логика простая

### Что оставить:
- Логику оркестрации перенести в `VoiceAssistant`
- Управление состоянием оставить в `VoiceAssistant`
- События оставить в `VoiceAssistant`

### Что убрать:
- Отдельный класс `VoiceOrchestrator`
- Прокси событий от оркестратора (строки 486-488)

## 4. ⚠️ УПРОСТИТЬ: Интерфейсы модулей

### Где находится:
- **Строки 359-396**: "1.1 Создать базовые интерфейсы модулей"

### Почему упростить:
- Интерфейсы хорошие, но слишком детальные
- `DeviceManager` можно упростить
- Не нужен отдельный `initialize()` для каждого модуля

### Что упростить:
```typescript
// Было:
export interface STTModule {
    initialize(config: STTConfig): Promise<void>;
    start(onTranscription: (text: string) => void): Promise<void>;
    stop(): Promise<void>;
    destroy(): Promise<void>;
}

// Стало:
export interface STTModule {
    start(onTranscription: (text: string) => void): Promise<void>;
    stop(): Promise<void>;
    destroy(): Promise<void>;
}
// initialize() вызывается в конструкторе или create()
```

## 5. ⚠️ УПРОСТИТЬ: DeviceManager

### Где находится:
- **Строки 384-389**: Интерфейс `DeviceManager`
- **Строки 859-925**: "4.1 Централизованный DeviceManager"

### Почему упростить:
- Слишком много методов
- `selectInput/selectOutput` можно заменить на простой конфиг

### Что оставить:
```typescript

export interface DeviceConfig {
    input?: string;   // ID или имя устройства
    output?: string;  // ID или имя устройства
}

// Использование существующего AudioDeviceManager
// Без дополнительных оберток
```

### Что убрать:
- Класс `VoiceDeviceManager`
- Методы `selectInput()`, `selectOutput()`
- Методы `getSelectedInput()`, `getSelectedOutput()`
- Просто передавать `AudioDeviceManager` напрямую в модули
