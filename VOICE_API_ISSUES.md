# Проблемы и несоответствия в документации VOICE_API.md

## ❌ Критические несоответствия

### 1. **Метод `stop()` не существует**
**Описано в документации:**
```typescript
await voice.stop();
```

**Реальность:**
- В классе `Voice` НЕТ метода `stop()`
- Есть только `destroy()` для полного освобождения ресурсов
- `startListening()` запускается автоматически после `initialize()` и работает до `destroy()`

**Исправление:** Удалить все упоминания `voice.stop()` из документации.

---

### 2. **Неправильное поведение `startListening()`**
**Описано в документации:**
> "Запускает прослушивание с ключевым словом"

**Реальность:**
- `startListening()` можно вызвать только если `state === VoiceState.LISTENING_FOR_KEYWORD`
- Но после `initialize()` state уже становится `LISTENING_FOR_KEYWORD`
- То есть метод фактически запускает транскрибер, но не меняет состояние

**Проблема:**
```typescript
public async startListening(): Promise<void> {
    if (this.state !== VoiceState.LISTENING_FOR_KEYWORD) {
        console.warn(`Нельзя начать прослушивание в состоянии ${this.state}.`);
        return;
    }
    if (!this.options.enableTranscription) {
        console.log("Распознавание речи отключено. Прослушивание невозможно.");
        return;
    }
    // ...
}
```

**Исправление:** Уточнить в документации, что `startListening()` нужно вызывать только для полного режима с транскрибацией.

---

### 3. **Автоматический запуск `startListening()` в конструкторе**
**Не описано в документации!**

**Реальность:**
В конце файла `voice.ts` есть автоматический запуск:
```typescript
(async () => {
    // ... код автозапуска
    await voice.initialize();
    await voice.startListening();
})();
```

Это означает, что при импорте модуля автоматически создается и запускается экземпляр Voice!

**Проблема:** Это может вызвать неожиданное поведение при импорте модуля в других файлах.

**Исправление:** 
1. Либо удалить автозапуск
2. Либо документировать это поведение
3. Либо сделать его опциональным

---

### 4. **`enableTTS` по умолчанию `false`, а не `true`**
**Описано в документации:**
```typescript
enableTTS?: boolean;  // По умолчанию true
```

**Реальность:**
```typescript
constructor(options: VoiceOptions = {}) {
    this.options = {
        // ...
        enableTTS: false, // Временно отключено для тестирования
        // ...
        ...options
    };
}
```

**Исправление:** Обновить документацию или изменить дефолтное значение на `true`.

## ⚠️ Неточности и упущения

### 5. **Отсутствует информация о состояниях (VoiceState)**
**Не описано в документации!**

**Реальность:**
Voice использует конечный автомат с состояниями:
```typescript
export enum VoiceState {
    IDLE,
    INITIALIZING,
    LISTENING_FOR_KEYWORD,
    RECORDING_COMMAND,
    AWAITING_AI_RESPONSE,
    SPEAKING,
    DESTROYING,
}
```

Многие методы проверяют текущее состояние и могут отказаться работать.

**Исправление:** Добавить раздел о жизненном цикле и состояниях.

---

### 6. **Метод `ask()` имеет ограничения по состоянию**
**Описано в документации:**
> "Отправляет текстовую команду в AI"

**Реальность:**
```typescript
public async ask(command: string): Promise<void> {
    if (!this.dialog) {
        console.error("Dialog не инициализирован. Вызовите initialize() сначала.");
        return;
    }
    if (this.state !== VoiceState.LISTENING_FOR_KEYWORD && 
        this.state !== VoiceState.RECORDING_COMMAND) {
        console.warn(`Вызов ask в состоянии ${this.state}. Может привести к неожиданному поведению.`);
    }
    // ...
}
```

Метод работает только в определенных состояниях!

**Исправление:** Документировать ограничения и предусловия для вызова `ask()`.

---

### 7. **Отсутствует экспорт интерфейсов**
**Описано в документации:**
```typescript
import { ITranscriber } from './lib/voice.js';
```

**Реальность:**
Нужно проверить, экспортируются ли `ITranscriber` и `ITextToSpeech` из модуля.

В коде есть:
```typescript
export interface ITranscriber { ... }
export interface ITextToSpeech { ... }
```

Но нет `export` для класса `Voice`!

**Проблема:** В конце файла:
```typescript
export default Voice;
```

Это default export, а не named export.

**Исправление:** Уточнить импорты в документации.

---

### 8. **Управление устройствами не интегрировано в Voice**
**Описано в документации:**
> "Выбор устройства ввода (микрофон)" с примерами использования

**Реальность:**
- `AudioDeviceManager` создается внутри `Voice` автоматически
- НЕТ способа передать выбранное устройство в `Voice` через опции
- `WhisperTranscriber` создает свой собственный `AudioDeviceManager`

**Проблема:**
```typescript
this.transcriber = this.options.transcriber || new WhisperTranscriber();
```

Если не передать кастомный транскрибер, то выбор устройства невозможен!

**Исправление:** 
1. Либо добавить опции для выбора устройств в `VoiceOptions`
2. Либо уточнить в документации, что нужен кастомный транскрибер

---

### 9. **Отсутствует информация о Dialog событиях**
**Не описано в документации!**

**Реальность:**
Voice использует события Dialog для управления потоком:
```typescript
private async handleDialogEvent(event: DialogEvent): Promise<void> {
    switch (event.type) {
        case 'ask':
        case 'ai_request':
        case 'ai_chunk':
        case 'ai_response':
        case 'tool_call':
        case 'tool_result':
        case 'done':
        case 'error':
    }
}
```

Пользователь не может подписаться на эти события напрямую!

**Исправление:** Добавить информацию о внутренних событиях или способе их отслеживания.

### 10. **TTS не работает с текущей реализацией**
**Описано в документации:**

**Реальность:**
```typescript
class ZonosTTSEngine implements ITextToSpeech {
    async speak(text: string): Promise<void> {
        // ... логика с zonosjs
    }
}
```

Но `zonosjs` требует отдельной установки и настройки, которая не описана!

**Исправление:** Добавить раздел о настройке Zonos или других TTS движков.

### 11. **Whisper модель по умолчанию - `tiny`, а не `base`**
**Не описано в документации!**

**Реальность:**
```typescript
const WHISPER_MODEL = 'tiny';
```

Модель `tiny` менее точная, чем `base`.

**Исправление:** Документировать используемую модель и как её изменить.

### 12. **Отсутствует информация о зависимостях**
**Не описано в документации!**

**Реальность:**
Voice требует:
- `whisper-node` для STT
- `zonosjs` для TTS (опционально)
- `chalk` для логирования
- `AudioDeviceManager` (встроенный)

**Исправление:** Добавить раздел "Зависимости" с инструкциями по установке.

---

### 13. **Метод `ask()` не возвращает результат**
**Описано в документации:**
```typescript
await voice.ask("Привет!");
```

**Реальность:**
```typescript
public async ask(command: string): Promise<void>
```

Метод ничего не возвращает! Результат можно получить только через события Dialog.

**Проблема:** Пользователь не может получить ответ AI напрямую из метода `ask()`.

**Исправление:** 
1. Либо изменить сигнатуру метода на `Promise<string>`
2. Либо документировать, как получить результат

---

### 14. **Примеры интеграции не протестированы**
**Описано в документации:**

- Отсутствия способа получить результат из `ask()`

**Исправление:** Протестировать примеры или пометить их как "концептуальные".
